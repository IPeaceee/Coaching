Lý thuyết

Đọc chuỗi quyền 10 ký tự

drwxr-xr-x
Loại: - file · d thư mục · l link u — user owner (chủ) g — group owner (nhóm) o — other (mọi người khác) 
$ ls -l
drwxr-xr-x. 2 test test123 4096 Dec  8 20:06 athena
-rw-r--r--. 1 test test456   33 Dec  8 19:48 .bash_logout
Kiểm tra theo thứ tựBạn là chủ? → dùng bộ u. Không phải chủ nhưng thuộc nhóm? → dùng bộ g. Không thì → bộ o. Chỉ áp dụng 1 bộ, không cộng dồn.

root bỏ qua mọi kiểm tra quyền đọc/ghi.

Lý thuyết · quan trọng nhất buổi

r w x trên FILE khác trên THƯ MỤC

QuyềnTrên FILETrên THƯ MỤC
r (read)Đọc nội dung (cat, less)Liệt kê tên file bên trong (ls)
w (write)Sửa nội dung fileTạo, xóa, đổi tên file bên trong (cần kèm x)
x (execute)Chạy file như chương trình/scriptĐi vào (cd) và truy cập file bên trong nếu biết tên
Hệ quả bất ngờ #1Xóa được file hay không phụ thuộc quyền w trên thư mục, không phải quyền trên file.
Hệ quả bất ngờ #2Để tới /a/b/c/file bạn cần x trên mọi thư mục /a, /a/b, /a/b/c.

Quyền dạng số (bát phân)

r = 4 · w = 2 · x = 1 · – = 0
SốQuyềnSốQuyền
0---4r--
1--x5r-x
2-w-6rw-
3-wx7rwx
SốChuỗiDùng cho
755rwxr-xr-xThư mục, script chung (mặc định thư mục)
644rw-r--r--File thường (mặc định file)
750rwxr-x---Thư mục của nhóm
700rwx------Thư mục riêng tư (~/.ssh)
600rw-------Khóa riêng, mật khẩu
400r--------Chỉ chủ được đọc
777rwxrwxrwx⚠ Gần như không bao giờ nên dùng

Ví dụ 705: chủ = 4+2+1 (rwx), nhóm = 0 (---), other = 4+1 (r-x).

Ví dụ

chmod — đổi quyền bằng số hoặc bằng chữ

$ touch 123.txt ; ls -l 123.txt
-rw-r--r--. 1 nhanle nhanle 0 Oct 19 19:38 123.txt
$ chmod 600 123.txt
$ chmod u+x 123.txt          # thêm x cho chủ
$ chmod go-w file.txt        # bỏ w của nhóm & other
$ chmod a+r file.txt         # a = all (u, g, o)
$ chmod u=rwx,g=rx,o= dir    # gán chính xác
$ chmod 700 -R athena/       # đệ quy cả bên trong
$ ls -l 123.txt
-rwx------. 1 nhanle nhanle 0 Oct 19 19:38 123.txt
chmod ugoa + - = rwx file
+Thêm quyền
-Bớt quyền
=Gán đúng bằng (xóa phần còn lại)
Ai được chmod?Chỉ chủ sở hữu của file và root.
Số hay chữ?Số: đặt lại toàn bộ. Chữ: sửa 1 phần, giữ nguyên phần còn lại.

Ví dụ

chown và chgrp — đổi chủ sở hữu

# mkdir /test-456
# ls -ld /test-456
drwxr-xr-x. 2 root root 6 Oct 31 19:20 /test-456
# chown u1 /test-456                  # đổi chủ
# chown u1:ketoan /test-456           # đổi chủ + nhóm
# chown :ketoan file.txt              # chỉ đổi nhóm
# chgrp ketoan file.txt               # = dòng trên
# chown -R apache:apache /var/www/site1
[u1@server1 ~]$ chmod 700 /test-456   # chủ được chmod
[u1@server1 ~]$ chown u2 /test-456
chown: changing ownership of '/test-456': Operation not permitted
chown user fĐổi chủ
chown user:group fĐổi chủ và nhóm
chown :group fĐổi nhóm
chgrp group fĐổi nhóm
-RĐệ quy
Chỉ root đổi chủUser thường không thể “cho” file của mình sang user khác (ghi chú gốc bài 6.4).

Lý thuyết

umask — quyền mặc định khi tạo mới

Quyền gốc: thư mục 777, file 666 (file mới không bao giờ tự có x). umask là các bit bị tắt đi.

umaskThư mục mớiFile mới
022 (mặc định)755644
027750640
077700600
002775664
Cách tính đúngBỏ những bit có trong umask: file 666 (rw-rw-rw-) bỏ 027 (----w-rwx) → rw-r----- = 640.
# umask
0022
# umask 027
# mkdir /test1 ; touch /test11
# ls -ld /test1 /test11
drwxr-x---. 2 root root 6 /test1
-rw-r-----. 1 root root 0 /test11
# umask 080
-bash: umask: 080: octal number out of range
Mẹo trong ghi chú gốc“777 − quyền mong muốn = umask; với file, chữ số lẻ thì trừ thêm 1” – cho kết quả đúng, nhưng hiểu theo cách “tắt bit” sẽ không bao giờ sai.

Lưu vĩnh viễn: thêm umask 027 vào ~/.bashrc.

Thí nghiệm: quyền OTHER trên thư mục

# mkdir /permission && echo file-test > /permission/file-test.txt
# chmod 750 /permission      # lần lượt: 750 751 752 753 755 777
# echo x > /permission/xoa-thu.txt   # tạo lại mỗi lượt
[u1@server1 ~]$ cd /permission
[u1@server1 ~]$ ls /permission
[u1@server1 ~]$ cat /permission/file-test.txt
[u1@server1 ~]$ touch /permission/u1.txt
[u1@server1 ~]$ rm -f /permission/xoa-thu.txt

Thư mục lồng nhau: quyền của thư mục cha

# mkdir -p /test-1/test-2
# echo test-1 > /test-1/test-1.txt
# echo test-2 > /test-1/test-2/test-2.txt
# chmod 750 /test-1 ; chmod 755 /test-1/test-2
[u1@server1 ~]$ cd /test-1/test-2
bash: cd: /test-1/test-2: Permission denied
# chmod 753 /test-1
[u1@server1 ~]$ cd /test-1/test-2 && ls
test-2.txt
[u1@server1 test-2]$ touch test-222
touch: cannot touch 'test-222': Permission denied
[u1@server1 test-2]$ touch ../test-222
  1. Vì sao lần đầu u1 không vào được test-2 dù test-2 là 755?
  2. Sau khi đổi /test-1 thành 753, vì sao u1 ls được trong test-2 nhưng không ls được trong test-1?
  3. Vì sao tạo file trong test-2 thất bại, còn trong test-1 lại thành công?
Đáp án
  1. Cần x trên mọi thư mục cha; /test-1 cho other ---.
  2. test-2 cho other r; test-1 cho other -wx (không có r).
  3. test-2: other không có w. test-1: other có -wx.

Lab B · 30 phút

Phân quyền mã nguồn web có chọn lọc

Thư mục /srv/webapp chứa thư mục con, file .txt, file .php. Yêu cầu:

  • Mọi thư mục: 755
  • Mọi file .txt: 600
  • Mọi file .php: 640, nhóm sở hữu apache
# mkdir -p /srv/webapp/{inc,admin/tools}
# touch /srv/webapp/{index,inc/db,admin/login}.php
# touch /srv/webapp/{readme,admin/tools/note}.txt
# chmod -R 777 /srv/webapp       # "lỡ tay"
Vì sao không dùng chmod -R?chmod -R 755 sẽ gán cả x cho mọi file. Cần phân biệt file và thư mục → dùng find.
Lời giải 
# find /srv/webapp -type d -exec chmod 755 {} \;
# find /srv/webapp -type f -name "*.txt" | xargs chmod 600
# find /srv/webapp -type f -name "*.php" -exec chmod 640 {} +
# find /srv/webapp -name "*.php" -exec chgrp apache {} +
# ls -lR /srv/webapp
## Cách gọn: X hoa = x chỉ cho thư mục
# chmod -R u=rwX,go=rX /srv/webapp

Bài tập

Luyện tập

  1. Đổi sang số: rwxr-x--x, rw-rw-r--, r--------.
    Đáp án751 · 664 · 400
  2. -rw-r----- 1 kt1 ketoan bc.txt. kt2 (nhóm ketoan) và ns1 (nhóm nhansu) làm được gì với file?
    Đáp ánkt2: chỉ đọc. ns1: không gì cả (other = ---).
  3. Vì sao chmod 644 script.sh rồi chạy ./script.sh bị “Permission denied”?
    Đáp ánThiếu quyền x. Sửa: chmod u+x script.sh (hoặc chạy bash script.sh).
  4. umask là 077. Thư mục và file mới có quyền gì?
    Đáp ánThư mục 700, file 600.
  5. Cho nhóm ketoan sở hữu toàn bộ /data/ketoan, nhóm có rwx, other không có gì.
    Đáp ánchgrp -R ketoan /data/ketoan; chmod -R g=rwX,o= /data/ketoan
  6. File /tmp/x có quyền 444 của root. User thường xóa được không? Vì sao?
    Đáp ánKhông – /tmp có sticky bit (drwxrwxrwt): chỉ chủ file mới xóa được. Sẽ học ở buổi 10.
