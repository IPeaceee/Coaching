Nhóm chính (primary group)

Mỗi user có đúng 1. File user tạo ra mang nhóm này. Mặc định trùng tên user.

Nhóm phụ (supplementary)

0 hoặc nhiều nhóm. Cho user thêm quyền của nhóm đó.
$ id g1
uid=1002(g1) gid=1003(giaovien) groups=1003(giaovien),1002(hocvien)

Vì sao hiện số?Linux lưu chủ sở hữu bằng UID, không phải tên. User bị xóa → chỉ còn số.
Rủi ro bảo mậtTạo user mới trùng UID cũ → user mới sở hữu toàn bộ dữ liệu cũ. Đôi khi là mục đích (bàn giao), đôi khi là sự cố.

Ghi chú gốc minh họa đúng tình huống này: tạo test_test với -u 502 để tiếp quản thư mục của antm_test.

Lý thuyết

su và sudo

su - user — “switch user”

Đăng nhập hẳn thành user khác, cần mật khẩu của user đích. su - = thành root. Dấu - nạp đầy đủ môi trường của user đích.

sudo lệnh — chạy 1 lệnh với quyền root

Cần mật khẩu của chính mình. Có ghi log (/var/log/secure), cấp quyền chi tiết được.
Thực tế doanh nghiệpKhóa đăng nhập root, mọi người dùng tài khoản riêng + sudo → biết ai làm gì.
[root@server1 ~]# usermod -aG wheel antm
[root@server1 ~]# su - antm
[antm@server1 ~]$ dnf install -y tree
Error: This command has to be run with superuser privileges
[antm@server1 ~]$ sudo dnf install -y tree
[sudo] password for antm:
Complete!
[antm@server1 ~]$ sudo -l            # mình được phép gì?
[antm@server1 ~]$ sudo -i            # mở shell root
[root@server1 ~]# exit
Nhóm quản trị sẵn cóRocky/RHEL: nhóm wheel · Ubuntu: nhóm sudo.

Ví dụ

visudo — cấp quyền chi tiết

## user  MÁY=(CHẠY_VỚI_USER)  LỆNH
root      ALL=(ALL)       ALL
antm    ALL=(ALL)       ALL                  # toàn quyền
%admin    ALL=(ALL)       ALL                  # % = cả nhóm
antm2   ALL=(ALL)       NOPASSWD: ALL        # không hỏi mật khẩu

## Chỉ được chạy 1 lệnh
test      ALL=(root)      /usr/bin/systemctl restart httpd

## Gom lệnh thành bí danh
Cmnd_Alias USERMGMT = /usr/sbin/useradd, \
                      /usr/bin/passwd [A-Za-z]*, \
                      !/usr/bin/passwd root
ns1       ALL=(root)      USERMGMT
Luôn dùng visudovisudo kiểm tra cú pháp trước khi lưu. Sửa /etc/sudoers bằng vi mà sai cú pháp → mất luôn quyền sudo.
Thực hành tốtĐặt quy tắc riêng trong /etc/sudoers.d/, không sửa file gốc.
Cảnh báo về “!” (dấu phủ định)ALL, !TEST như ghi chú gốc không an toàn: user vẫn lách được (vd sudo -i hoặc chép /bin/vi sang tên khác). Hãy cấp danh sách lệnh được phép thay vì cấm.

Tạo hệ thống tài khoản cho công ty

  1. Chuẩn bị /etc/skel: thư mục TaiLieu và file noi-quy.txt
  2. Tạo nhóm ketoan, nhansu, giamdoc
  3. Tạo kt1, kt2 (nhóm chính ketoan), ns1 (nhóm chính nhansu), gd1 (nhóm chính giamdoc, nhóm phụ ketoan + nhansu). Mật khẩu Lpi@2026
  4. Kiểm tra bằng id và /etc/group; home của mọi user có TaiLieu
  5. kt1 phải đổi mật khẩu lần đầu đăng nhập; mật khẩu hết hạn sau 90 ngày
  6. kt2 nghỉ phép: khóa tài khoản, thử đăng nhập → thất bại → mở khóa
  7. gd1 có toàn quyền sudo (thêm vào wheel)
  8. ns1 chỉ được sudo: useradd và đổi mật khẩu user khác, trừ root
  9. Xóa kt2 giữ home; tìm file mồ côi
Cách kiểm traMở phiên thứ 2 và đăng nhập thật bằng từng user (su - kt1 hoặc SSH) để thấy kết quả – đừng chỉ đọc file.

Bài tập

Luyện tập

  1. Tạo user web không đăng nhập được, home ở /srv/web.
    Đáp ánuseradd -d /srv/web -s /sbin/nologin web
  2. Thêm antm vào nhóm docker mà không mất các nhóm phụ hiện có.
    Đáp ánusermod -aG docker antm (hoặc gpasswd -a antm docker)
  3. Liệt kê tên các user có UID ≥ 1000.
    Đáp ánawk -F: '$3>=1000 {print $1}' /etc/passwd
  4. Dòng test:!!:20380:0:99999:7::: trong shadow cho biết điều gì?
    Đáp ánUser test chưa được đặt mật khẩu (hoặc bị khóa) – không đăng nhập bằng mật khẩu được.
  5. Viết dòng sudoers cho nhóm webadmin được restart httpd mà không cần mật khẩu.
    Đáp án%webadmin ALL=(root) NOPASSWD: /usr/bin/systemctl restart httpd

Trắc nghiệm nhanh · 5 phút

Kiểm tra trước khi về

  1. Thêm antm vào nhóm docker mà không mất các nhóm phụ đang có?
    Đáp ánusermod -aG docker antm
  2. Buộc kt1 đổi mật khẩu ở lần đăng nhập tới?
    Đáp ánchage -d 0 kt1 (hoặc passwd -e kt1).
  3. Vì sao phải sửa sudo bằng visudo?
    Đáp ánvisudo kiểm tra cú pháp trước khi lưu – sai cú pháp có thể mất quyền sudo.
