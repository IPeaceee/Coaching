Lý thuyết

Ba quyền đặc biệt — chữ số thứ tư

QuyềnSốKý hiệuTrên FILE chạy đượcTrên THƯ MỤC
SUID4rws------ (vị trí x của u)Chạy với quyền của chủ file— (không tác dụng)
SGID2---rws--- (vị trí x của g)Chạy với quyền của nhóm fileFile tạo bên trong kế thừa nhóm của thư mục

# chmod 2775 dir       # = chmod g+s
# chmod 1777 dir       # = chmod o+t
# chmod 3770 dir       # SGID + sticky
Chữ thường hay hoa?s/t = có cả x bên dưới. S/T = đặt quyền đặc biệt nhưng thiếu x (thường là cấu hình sai, trừ trường hợp sticky trên thư mục không cho other).

Ví dụ

SUID — vì sao user thường đổi được mật khẩu?

$ ls -l /etc/shadow /usr/bin/passwd
----------. 1 root root   980 /etc/shadow
-rwsr-xr-x. 1 root root 32648 /usr/bin/passwd
# find / -perm -4000 -type f 2>/dev/null
/usr/bin/passwd
/usr/bin/su
/usr/bin/sudo
/usr/bin/mount
...

/etc/shadow không ai ghi được, nhưng passwd có SUID của root → khi nhanle chạy, tiến trình mang quyền root và ghi được mật khẩu mới.

Demo: vì sao SUID nguy hiểm

# cp /usr/bin/cat /usr/local/bin/mycat
# chmod u+s /usr/local/bin/mycat
[u1@server1 ~]$ cat /etc/shadow
cat: /etc/shadow: Permission denied
[u1@server1 ~]$ mycat /etc/shadow | head -1
root:$6$Kx...:20380:0:99999:7:::
# rm -f /usr/local/bin/mycat      # dọn ngay!
Bảo mậtĐịnh kỳ rà soát file SUID lạ. Kẻ tấn công rất thích để lại “cửa hậu” SUID.

Ví dụ

SGID trên thư mục — giữ đúng nhóm cho file chung

# groupadd hocvien ; useradd -g hocvien u3 ; useradd batky
# mkdir /shared ; chgrp hocvien /shared ; chmod 777 /shared
[u3@server1 ~]$ echo u3 > /shared/u3.txt
[batky@server1 ~]$ echo bk > /shared/batky.txt
# ls -l /shared
-rw-r--r--. 1 batky batky   3 batky.txt     ← nhóm lộn xộn
-rw-r--r--. 1 u3    hocvien 3 u3.txt
# groupadd giaovien ; chgrp giaovien /shared
# chmod g+s /shared ; ls -ld /shared
drwxrwsrwx. 2 root giaovien 40 /shared
[batky@server1 ~]$ echo bk > /shared/batky-1.txt
[u3@server1 ~]$ echo u3 > /shared/u3-1.txt
# ls -l /shared | grep -- -1
-rw-r--r--. 1 batky giaovien 3 batky-1.txt  ← theo thư mục
-rw-r--r--. 1 u3    giaovien 3 u3-1.txt

Không có SGID: file mang nhóm chính của người tạo → đồng nghiệp cùng phòng không đọc/sửa được theo quyền nhóm.

Có SGID: file mới mang nhóm của thư mục, bất kể ai tạo.

Chỉ ảnh hưởng file MỚIFile có sẵn trước khi đặt SGID không bị đổi nhóm (ghi chú gốc bài 6.5).
Thư mục nhóm chuẩnchgrp nhom dir; chmod 2770 dir

Ví dụ

Sticky bit — cùng ghi được nhưng không xóa của nhau

# useradd -g giaovien g1 ; useradd -g giaovien g2
# mkdir /baigiang ; chown g1:giaovien /baigiang
# chmod 775 /baigiang
[g1@server1 ~]$ echo bai1 > /baigiang/g1_bai.txt
[g2@server1 ~]$ mv /baigiang/g1_bai.txt /baigiang/g2_bai.txt
## THÀNH CÔNG – g2 đổi tên bài của g1!
# chmod o+t /baigiang ; ls -ld /baigiang
drwxrwxr-t. 2 g1 giaovien 6 /baigiang
[g1@server1 ~]$ echo bai2 > /baigiang/g1_bai2.txt
[g2@server1 ~]$ rm /baigiang/g1_bai2.txt
rm: cannot remove '/baigiang/g1_bai2.txt': Operation not permitted
$ ls -ld /tmp
drwxrwxrwt. 12 root root 4096 /tmp

Có sticky bit, người được xóa / đổi tên một file chỉ gồm:

  • chủ của file đó
  • chủ của thư mục
  • root
Ví dụ kinh điển/tmp = 1777: ai cũng ghi được, không ai xóa được file của người khác.
Sticky không chặn SỬA nội dungNếu file có quyền w cho nhóm, g2 vẫn sửa được nội dung – chỉ không xóa/đổi tên.

Lý thuyết ngoài đề LPIC-1 · cần cho công việc

Vì sao cần ACL?

chmod chỉ có 3 đối tượng: 1 chủ, 1 nhóm, còn lại. Bài toán thực tế:

“Thư mục /data-shared của root. Cho g1 toàn quyền, g2 chỉ đọc, nhóm giaovien đọc, còn lại cấm.”

→ cần nhiều user/nhóm với quyền khác nhau trên cùng một đối tượng → ACL (Access Control List).

$ getfacl /data-shared
\# file: data-shared
\# owner: root
\# group: root
user::rwx
group::r-x
other::---
Ghi chú gốc (CentOS 5/6)Phải thêm acl vào /etc/fstab và mount -o remount /. Ext4/XFS hiện đại bật ACL sẵn – không cần nữa.

Ví dụ ngoài đề LPIC-1

setfacl / getfacl

# mkdir /data-shared ; chmod 750 /data-shared
# setfacl -m u:g1:rwx /data-shared
# setfacl -m u:g2:r-x /data-shared
# setfacl -m g:giaovien:r-x /data-shared
# ls -ld /data-shared
drwxrwx---+ 2 root root 6 /data-shared   ← dấu +
# getfacl /data-shared
\# file: data-shared
user::rwx
user:g1:rwx
user:g2:r-x
group::r-x
group:giaovien:r-x
mask::rwx
other::---
# setfacl -x u:g2 /data-shared        # gỡ 1 mục
# setfacl -b /data-shared             # gỡ toàn bộ ACL
-m u:user:rwxThêm/sửa quyền cho user
-m g:nhom:r-xThêm/sửa quyền cho nhóm
-m u:user:---Cấm riêng 1 user
-x u:userGỡ mục ACL của user
-bGỡ mọi ACL mở rộng
-RĐệ quy
-d -m …ACL mặc định (cho file mới)
getfacl -R d > fSao lưu ACL
setfacl --restore=fKhôi phục ACL

Lý thuyết ngoài đề LPIC-1

Mask, ACL mặc định và “cấm riêng 1 người”

Mask = trần quyền

# chmod g=rx /data-shared     # chmod nhóm = sửa MASK
# getfacl /data-shared | grep g1
user:g1:rwx       #effective:r-x

Quyền thật của user/nhóm có tên = quyền ghi trong ACL ∩ mask. Trên file có ACL, chmod g=… thực chất đổi mask.

Cấm riêng 1 user

# mkdir /cho-moi-nguoi              # 755: ai cũng vào
# setfacl -m u:g3:--- /cho-moi-nguoi
[g3@server1 ~]$ cd /cho-moi-nguoi
bash: cd: /cho-moi-nguoi: Permission denied

ACL mặc định — kế thừa cho file mới

# setfacl -d -m g:giaovien:rwx /data/giao_vien
[g1@server1 ~]$ touch /data/giao_vien/bai.txt
# getfacl /data/giao_vien/bai.txt | grep giaovien
group:giaovien:rw-
Ghi chú gốc: “ACL lấy quyền thấp nhất”Chính xác hơn: mỗi đối tượng được kiểm tra riêng. Nhóm có rwx trên thư mục, nhưng khi g1 chmod 600 file của mình thì mask của file thành --- → nhóm không đọc được file đó.
Giữ ACL khi sao chépcp -a giữ ACL; cp thường thì không. tar --acls khi sao lưu.

Thư mục dùng chung cho giáo viên & sinh viên

/data                    root:root 750
├── giao_vien/          root:root 750
│     bai-giang.txt
└── sinh_vien/          root:root 750
      tai-lieu.txt

Nhóm giaovien: g1, g2, g3
Nhóm sinhvien: s1, s2
User ngoài:    u1
  1. giaovien: xem được /data, vào được cả 2 thư mục con
  2. sinhvien: đi xuyên qua /data nhưng không xem được trong đó có gì; chỉ vào được sinh_vien
  3. giao_vien: giáo viên tạo được file; nhưng không xóa/đổi tên file của nhau
  4. File giáo viên tạo trong giao_vien tự động cho cả nhóm đọc & sửa
  5. sinh_vien: sinh viên nộp bài (tạo file), không xóa bài của nhau; giáo viên chỉ đọc
  6. u1 không làm được gì
Lab phỏng theo "Lab_On_Tap_Chmod_Permission" trong ghi chú gốc, bổ sung ACL mặc định để giải quyết vấn đề g1 chmod 600 làm g2 không đọc được.

Bài tập

Luyện tập

  1. -rwSr--r-- nghĩa là gì? Có vấn đề gì không?
    Đáp ánĐặt SUID nhưng chủ không có x → SUID vô tác dụng, thường là cấu hình sai.
  2. Tạo thư mục /phongban/ketoan cho nhóm ketoan: file mới tự thuộc nhóm ketoan, thành viên không xóa file của nhau, người ngoài không vào được.
    Đáp ánmkdir -p /phongban/ketoan; chgrp ketoan /phongban/ketoan; chmod 3770 /phongban/ketoan
  3. Cho riêng user kiemtoan quyền đọc toàn bộ /phongban/ketoan (cả file tạo sau này).
    Đáp ánsetfacl -R -m u:kiemtoan:rX /phongban/ketoan; setfacl -d -m u:kiemtoan:rX /phongban/ketoan
  4. Liệt kê mọi file SGID trên hệ thống.
    Đáp ánfind / -perm -2000 -type f 2>/dev/null
  5. Dấu + cuối chuỗi quyền drwxr-x---+ báo hiệu gì? Xem chi tiết bằng lệnh nào?
    Đáp ánCó ACL mở rộng. Xem bằng getfacl.
