Lý thuyết

Tiến trình (process) là gì?

Mỗi chương trình đang chạy là một tiến trình, có:

  • PID – mã số duy nhất
  • PPID – PID của tiến trình cha
  • User chạy nó, % CPU, % RAM, trạng thái

PID 1 = systemd – cha của mọi tiến trình.

Dịch vụ (daemon)Tiến trình chạy nền liên tục, tên thường kết thúc bằng d: sshd, httpd, crond.
$ ps
    PID TTY          TIME CMD
   1450 pts/0    00:00:00 bash
   1502 pts/0    00:00:00 ps
$ ps aux | less        # mọi tiến trình, đủ cột
$ ps -eo pid,ppid,user,comm | head -3
    PID    PPID USER     COMMAND
      1       0 root     systemd
      2       0 root     kthreadd
$ ps -ef | grep sshd
$ ps -p 1021
$ pgrep -l sshd
1021 sshd
$ pstree | head -5

Dừng tiến trình: kill, pkill, killall

Tín hiệuSốÝ nghĩa
SIGTERM15“Vui lòng dừng” – chương trình dọn dẹp, lưu dữ liệu rồi thoát. Mặc định
SIGKILL9Kernel “giết” ngay – có thể mất dữ liệu
SIGHUP1Nhiều daemon hiểu là “đọc lại cấu hình”
SIGINT2Giống bấm Ctrl+C
Quy trình chuẩnThử kill PID (15) trước → đợi vài giây → vẫn còn mới kill -9 PID.
$ sleep 1000 &
[1] 1720
$ ps -p 1720
    PID TTY          TIME CMD
   1720 pts/0    00:00:00 sleep
$ kill 1720
[1]+  Terminated              sleep 1000
$ kill -9 1735
$ kill -l             # liệt kê mọi tín hiệu
$ pkill -u test       # dừng mọi tiến trình của user test
$ killall yes         # theo tên chương trình

Chạy nền và job control

Lý thuyết · LPI 103.6

Độ ưu tiên: nice và renice

-20 ← ưu tiên cao · 0 mặc định · ưu tiên thấp → 19
  • Niceness càng cao, tiến trình càng “nhường” CPU cho người khác
  • nice lệnh không ghi -n = niceness 10
  • User thường chỉ được tăng niceness; chỉ root được giảm (tăng ưu tiên)
  • Cột NI trong top/ps; cột PR = 20 + NI
Khi nào dùng?Nén sao lưu, quét virus, biên dịch… chạy với nice -n 19 để web server không bị chậm.
$ nice -n 19 tar -czf /tmp/etc.tgz /etc 2>/dev/null &
[1] 2345
$ ps -o pid,ni,comm -p 2345
    PID  NI COMMAND
   2345  19 tar
$ yes > /dev/null &
[2] 2350
$ renice -n 15 -p 2350
2350 (process ID) old priority 0, new priority 15
$ renice -n 5 -p 2350
renice: failed to set priority for 2350 (process ID): Permission denied
# renice -n -5 -p 2350

Ví dụ

Nén từng file: gzip · bzip2 · xz

$ seq 1000000 > 1trieu.txt
$ gzip  -k 1trieu.txt     # -k: giữ file gốc
$ bzip2 -k 1trieu.txt
$ xz    -k 1trieu.txt
$ ls -lh 1trieu*
$ gzip -c 1trieu.txt > ban-sao.gz   # ghi ra stdout
$ gunzip 1trieu.txt.gz        # = gzip -d
$ bunzip2 1trieu.txt.bz2      # = bzip2 -d
$ unxz 1trieu.txt.xz          # = xz -d
$ zcat ban-sao.gz | head -3   # đọc không cần giải nén
Công cụĐuôiTốc độTỷ lệ nén
gzip.gzNhanh nhấtKhá
bzip2.bz2Chậm hơnTốt hơn
xz.xzChậm nhấtTốt nhất
Chú ýMặc định gzip file thay thế file gốc bằng file.gz. Dùng -k hoặc -c > để giữ lại.
Quan trọnggzip/bzip2/xz chỉ nén từng file. Muốn nén cả thư mục → đóng gói bằng tar trước.

Ví dụ

tar — đóng gói (và nén) thư mục

$ tar -cvf test.tar test1 test2       # chỉ đóng gói
$ tar -czvf test.tar.gz test          # + nén gzip
$ tar -cjvf test.tar.bz2 test         # + nén bzip2
$ tar -cJvf test.tar.xz test          # + nén xz
$ tar -tzvf test.tar.gz               # xem bên trong
$ tar -xzvf test.tar.gz               # giải nén tại chỗ
# tar -xvf test.tar.gz -C /opt        # giải nén vào /opt
Cách nhớcreate · extract · list + z gzip · j bzip2 · J xz + verbose + f tên file (luôn đứng cuối cụm).
-cTạo gói mới
-xGiải nén
-tLiệt kê nội dung
-z -j -JNén gzip / bzip2 / xz
-vHiện tên file đang xử lý
-f fileTên file tar
-C dirGiải nén vào thư mục dir
-pGiữ nguyên quyền

Khi giải nén, tar -xf tự nhận diện kiểu nén – không bắt buộc z/j/J.

Ví dụ · LPI 103.3

cpio và dd — hai công cụ “cổ” vẫn có trong đề

cpio: đóng gói theo danh sách file từ stdin

$ find congty -name "*.txt" | cpio -ov > congty.cpio
$ cpio -tv < congty.cpio          # liệt kê
$ mkdir /tmp/x && cd /tmp/x
$ cpio -idv < ~/congty.cpio       # i: giải, d: tạo thư mục

-o copy-out (tạo) · -i copy-in (giải) · -t liệt kê. initramfs (B14) và gói RPM (B7) bên trong đều là cpio.

dd: chép từng byte giữa file và thiết bị

# dd if=/dev/sda of=/root/mbr.bin bs=512 count=1
# dd if=/dev/zero of=/root/disk.img bs=1M count=1024
# dd if=rocky.iso of=/dev/sdX bs=4M status=progress
if= / of=Nguồn / đích
bs= · count=Kích thước khối · số khối
Cực kỳ cẩn thậnGõ nhầm of=/dev/sda là mất sạch ổ đĩa, không hỏi lại.
Liên kết/root/disk.img 1 GB sẽ làm “ổ đĩa ảo” cho lab gdisk/fsck ở B11.

Lab A · 35 phút

Xử lý tiến trình “ăn” CPU

  1. Mở 2 phiên SSH/console vào server (cùng user thường)
  2. Phiên 1: chạy yes > /dev/null & ba lần (nhiều hơn số CPU). Ghi lại 3 PID
  3. Phiên 2: chạy top, sắp xếp theo CPU. renice -n 19 một tiến trình – %CPU của nó thay đổi thế nào?
  4. Dùng ps aux | grep yes và pgrep yes để tìm PID
  5. Dừng tiến trình thứ nhất bằng SIGTERM, tiến trình thứ hai bằng phím k trong top
  6. Chạy sleep 600, tạm dừng bằng Ctrl+Z, cho chạy nền bằng bg, kiểm tra jobs, rồi fg và Ctrl+C
  7. Tìm xem tiến trình nào đang mở cổng 22, PID của nó là bao nhiêu
  8. Ghi lại: RAM available, % dùng của /, thư mục lớn nhất trong /var

Lab B · 35 phút

So sánh thuật toán nén & sao lưu /etc

  1. Tạo ~/lab6/1trieu.txt bằng seq 1000000

Bài tập

Luyện tập

  1. Tìm PID của tiến trình crond bằng 2 cách khác nhau.
    Đáp ánpgrep crond · ps aux | grep crond · pidof crond
  2. Tiến trình PID 2345 không chịu dừng với kill 2345. Làm gì tiếp?
    Đáp ánkill -9 2345 (SIGKILL) – chấp nhận rủi ro mất dữ liệu chưa lưu.
  3. Thư mục nào trong /usr chiếm nhiều dung lượng nhất?
    Đáp ándu -sh /usr/* | sort -h | tail -1
  4. Đóng gói thư mục ~/congty thành file nén bzip2.
    Đáp ántar -cjvf congty.tar.bz2 ~/congty
  5. Xem file backup.tar.xz có chứa gì mà không giải nén.
    Đáp ántar -tJvf backup.tar.xz (hoặc tar -tvf)
  6. Cổng nào trên máy đang được tiến trình chronyd lắng nghe?
    Đáp ánss -tulnp | grep chronyd → UDP 323.

Trắc nghiệm nhanh · 5 phút
